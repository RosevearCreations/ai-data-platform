# AI Data Platform Build 430

## Source-Signed Sweep Challenge V1.2, Overlapping-Sweep Isolation Certification, Repeated YW/iCamp Deployment & Offline Reliability History, and Hosted Cadence Baseline

Build 430 strengthens the Build 429 receipt-bound sweep model. Build 429 made each AIDP observation point at the exact receipt returned by that probe. Build 430 adds an unpredictable 256-bit challenge generated by AIDP, returned by the source inside the Ed25519-signed payload, and verified against the challenge AIDP actually sent.

## Protocol 1.2

The source endpoint remains backward compatible. A request without the challenge header can still receive protocol 1.1. A valid `x-rosevear-telemetry-challenge` header produces protocol 1.2 and adds the exact challenge to the signed payload. A malformed challenge is rejected before signing.

AIDP Build 430 accepts a challenge probe only when:
- the source is pinned to the exact expected production commit;
- the Ed25519 signature and public-key fingerprint pass;
- freshness, privacy boundary and anti-replay controls pass;
- protocolVersion is 1.2;
- the signed challenge exactly equals the random challenge AIDP sent.

## Overlapping-sweep isolation

Production acceptance performs two simultaneous independent challenge probes per source for Yard Workers and iCamp. Each source must return two verified challenge-bound receipts. The two challenges and two receipt IDs must be distinct. This closes the remaining practical overlap ambiguity that Build 429 deliberately left as a future protocol goal.

## Reliability and deployment history

Every normal Build 430 sweep records a reliability event for YW and iCamp. The first Build 430 observation compares against the latest Build 429 production evidence, allowing a genuine source-commit change to be recorded as DEPLOYMENT_CHANGE_VERIFIED. Later events distinguish online continuity, observed offline/held intervals and a verified return after an outage.

Build 430 does not deliberately take a production source offline just to create an outage sample. OFFLINE_OR_HELD is written only when a real scheduled, production or operator challenge fails.

## Hosted cadence baseline

The protected Vercel cron remains `17 12 * * *`, a daily hosted floor. The dashboard measures actual Build 430 sweep intervals and separately identifies manual/production observations. A daily Hobby-plan floor is not renamed as five-minute uptime.

## Production gate

A production build passes only when:
1. YW and iCamp each pass a fresh v1.2 signed challenge sweep;
2. a second sequential sweep returns new challenge and receipt IDs for both;
3. two concurrent challenges per source remain isolated and independently signed;
4. migration 0193 and historical release verification pass;
5. the final Vercel production deployment reaches READY.

The other five source HOLD states remain governed by Build 429 and are not promoted by inference.
